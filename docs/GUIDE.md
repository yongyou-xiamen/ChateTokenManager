## 快速开始

### 产品介绍

ChateTokenManager 是面向企业的 AI 资源纳管平台,帮助企业管理 AI 资产、控制 AI 成本、衡量 AI 价值。管理员可以统一接入和分配 AI 资源,员工使用自己的 AI 身份访问所需工具,管理者可以持续查看使用量、成本和预算情况。

#### 为什么使用 ChateTokenManager

企业开始大规模使用 AI 后,通常会遇到几类实际问题:

- 模型和工具分散在不同供应商、账号和团队中,无法统一管理。
- 员工各自保存密钥,人员变动后难以及时收回权限。
- 不清楚哪些部门在使用 AI,也无法把成本归到具体人员、项目或模型。
- 高成本模型、内部 Skill 和 MCP Server 缺少统一申请、审批和分发入口。
- 出现异常调用后,缺少可查询的用户、Key、模型、用量和管理操作记录。

ChateTokenManager 把这些工作集中到管理后台。员工不需要接触供应商密钥,只使用自己的 AI 身份和管理员分配的资源。

#### 三类用户

**企业负责人** 通过 Dashboard 和 AI 效能页面查看人员覆盖、调用趋势、模型使用、成本和预算执行情况。需要进一步分析时,可以按部门、项目、人员和模型查看数据。

**平台管理员** 负责日常配置和支持工作:
- 接入企业采购或自建的模型服务。
- 创建模型并完成可用性测试。
- 建立人员、部门和项目。
- 给员工分配 AI 身份、资源、预算和调用限制。
- 发布模型、Skill、MCP Server 和智能体。
- 处理员工申请,查询调用记录和管理操作记录。

**普通员工** 登录用户端后,可以查看自己的 AI 身份、已获授权的资源和本月用量。在模型广场或 AI 市场申请需要的资源,再把接入信息配置到 Claude Code、Codex、WorkBuddy 等工具中。

#### 主要功能

| 功能 | 能做什么 |
|------|---------|
| 模型纳管 | 统一接入不同供应商和自建模型,配置多条可用线路并执行连通性测试 |
| AI 身份 | 为人员、部门和项目创建 Key,分配模型与工具,设置预算和调用限制 |
| AI 市场 | 发布和分发 Skill、MCP Server 与智能体,支持申请和审批 |
| AI 效能 | 查看使用覆盖、调用趋势、模型成本、预算进度和运营报表 |
| 安全与审计 | 查询管理操作,检查 Skill 风险,处理 Key 泄露和异常调用 |
| 平台设置 | 修改平台显示名称、Logo 和浏览器图标 |

#### 第一次使用

**管理员** 如果平台已经部署完成,建议按这个顺序开始:
1. 进入「供应商类型与接入格式」,确认上游类型和接口格式。
2. 按「供应商与凭证」保存服务地址和密钥。
3. 按「模型与部署」创建模型、添加可用线路并测试。
4. 发布模型,再为测试用户分配 AI 身份和模型权限。
5. 使用测试用户登录用户端,完成一次真实调用。

**普通员工**:
1. 使用管理员提供的账号登录用户端。
2. 打开「我的 AI 身份」,确认状态为「已激活」。
3. 打开模型广场或 AI 市场,申请所需资源。
4. 审批通过后复制 Key、Endpoint 和模型 ID。
5. 按对应的客户端文档完成配置。

### 部署

使用 Docker Compose 安装、验证、升级和备份 ChateTokenManager。

#### 部署前准备

| 项目 | 要求 |
|------|------|
| Docker | 20.10 或更高 |
| Docker Compose | v2,命令为 `docker compose` |
| 主机配置 | 最低 4 核 CPU、8 GB 内存 |
| 磁盘 | 为业务数据、日志、上传文件和备份预留空间 |
| 网络 | 准备用户端地址、管理后台地址和客户端 Endpoint |

生产环境还应准备固定域名或 IP、时间同步、HTTPS 证书、备份位置和访问控制策略。

#### 下载安装

```bash
git clone https://github.com/yongyou-xiamen/ChateTokenManager.git
cd ChateTokenManager
cp .env.example .env
```

先编辑 `.env`,再启动:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

首次启动需要拉取镜像并初始化数据,请等待服务进入 `running` 或 `healthy` 状态。

#### 必须确认的配置

| 配置 | 要求 |
|------|------|
| 数据存储密码 | 使用随机强密码,不使用示例值 |
| 登录签名密钥 | 使用足够长的随机值并安全备份 |
| 超级管理员初始密码 | 部署前修改,首次登录后再次修改 |
| 加密密钥 | 首次设置后妥善保存,升级和恢复时必须沿用 |
| 服务域名或 IP | 填写用户和客户端实际可访问的地址 |
| 平台版本 | 生产环境固定到明确版本,不使用不确定标签 |

完整字段和示例值以当前版本随附的 `.env.example` 为准。环境密钥不要提交到代码仓库。

#### 访问地址

| 地址 | 用途 |
|------|------|
| `http://<host>` | 用户端 |
| `http://<host>/admin` | 管理后台 |
| `http://<host>/api/docs` | 管理 API 文档 |
| 管理员配置的 Endpoint | Claude Code、Codex、WorkBuddy 等客户端 |

如果服务器位于公网,建议只允许公司出口、VPN 或受控反向代理访问。启用 HTTPS 后,确认模型广场显示的 Endpoint 与客户端实际使用的地址一致。

#### 首次登录

1. 打开 `http://<host>/admin`。
2. 用户名填写 `admin`。
3. 使用部署配置中的超级管理员初始密码。
4. 登录后立即修改密码。
5. 打开 Dashboard,确认页面可以正常加载。

初始密码只用于第一次创建管理员。平台已有 `admin` 后,修改部署文件不会自动重置现有密码。

#### 部署验证

```bash
docker compose ps
docker compose logs
```

再用 admin 账号登录管理后台,确认 Dashboard 加载正常。然后用测试用户登录用户端,完成一次模型调用,确认链路通畅。

#### 升级

```bash
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=50
```

升级前建议备份数据库:

```bash
docker exec <db_container> pg_dump -U <user> <db> > backup_$(date +%Y%m%d).sql
```

#### 使用 GHCR 镜像

本项目通过 GitHub Actions 自动构建并推送镜像到 GHCR。配置流程:
1. `.github/workflows/docker-build.yml` 已配置自动构建。
2. push 到 `main` 分支触发构建,镜像推送到 `ghcr.io/yongyou-xiamen/chate-token-manager:latest`。
3. 部署时在 `docker-compose.yml` 中把 aihelms 服务 image 改为:
   ```yaml
   image: ghcr.io/yongyou-xiamen/chate-token-manager:latest
   ```
4. 私有镜像需要先 `docker login ghcr.io`。

### API 介绍

创建管理 API Key,让受信任的第三方系统调用 ChateTokenManager 管理 API。

#### 使用前确认

管理 API Key 权限等同管理员。创建前应确认:
- 对接系统由企业管理,并且有明确负责人。
- Key 只保存在服务端,不会下发到浏览器、桌面客户端或移动端。
- 已确定用途、调用来源、有效期和停用流程。
- 不把同一个 Key 分给多个无法区分的系统。

#### 新建 API Key

进入「安全 > API Key」,点击「新建 API Key」。

| 字段 | 必填 | 填写建议 |
|------|------|---------|
| 名称 | 是 | 使用「系统名-环境」,例如 oa-prod |
| 描述 | 否 | 写清用途、负责人和对接系统 |
| 过期时间 | 否 | 有明确项目周期时设置;留空表示不过期 |

点击「创建」后,列表会显示新 Key。立即复制到对接系统的密钥存储中,不要写进代码仓库、配置样例或工单正文。

#### 请求管理 API

基础路径通常是:`http://<地址>/api/v1`

请求头:`Authorization: Bearer <管理 API Key>`

示例(读取供应商列表):
```bash
curl "http://<地址>/api/v1/providers?page=1&page_size=20" \
  -H "Authorization: Bearer <管理 API Key>"
```

成功时返回 code、message 和 data。具体字段以当前部署版本的接口文档为准。

#### 查看接口文档

浏览器打开 `http://<地址>/api/docs`,点击「Authorize」,输入管理 API Key,再选择接口进行测试。测试创建、修改和删除类接口时,先使用非生产数据,并记录测试对象。

#### 状态与有效期

API Key 列表显示:当前状态(启用/禁用/已过期)、创建时间、最后使用时间、过期时间。

「最后使用」长期为空时,先确认对接系统是否真的发送了该 Key,以及请求是否到达当前环境。

#### 禁用和删除

- **临时停用**:点击「禁用」后,使用该 Key 的新请求会被拒绝。故障排查、系统下线或发现异常来源时,优先禁用,确认无影响后再决定是否删除。
- **永久删除**:删除前确认对接系统已经换用新 Key 或停止调用。删除后无法恢复。
- **轮换 Key**:新建 → 更新到对接系统 → 观察新 Key「最后使用」→ 禁用旧 Key → 确认业务正常 → 删除旧 Key。

#### 常见问题

| 现象 | 检查方法 |
|------|---------|
| 401 | Key 是否完整、是否禁用、是否过期,Authorization 格式是否正确 |
| 403 | 当前接口是否允许 API Key 身份访问,或接口权限要求是否变化 |
| 404 | 地址是否包含 /api/v1,接口路径是否属于当前版本 |
| 浏览器调用暴露 Key | 不要在前端直接调用,改由企业后端服务代理 |
| 无法判断哪个系统在调用 | 为每个系统和环境创建独立 Key,不要共用 |

> 模型调用所需的 Key 请查看用户指南,不要使用管理 API Key。

### AI 身份

按部门、项目、人员和 AI 身份管理用户权限。

#### 创建部门或项目

1. 进入「AI 身份 > 部门管理」,创建部门并设置上级部门。
2. 跨部门项目进入「AI 身份 > 项目管理」创建。
3. 保存后返回人员管理创建用户。

不需要部门或项目时可以直接创建用户。

#### 创建用户

1. 进入「AI 身份 > 人员管理」。
2. 点击右上角「新建用户」。
3. 填写用户信息。
4. 点击「保存」。

| 字段 | 填写方法 |
|------|---------|
| 用户名 | 员工登录名,不能与已有用户重复 |
| 邮箱 | 填有效邮箱地址 |
| 姓名 | 填审批和用户端显示名称 |
| 密码 | 设置初始密码,至少 6 位 |
| 角色 | 普通员工选普通用户;需要进入管理后台时才分配管理员角色 |
| 部门 | 从部门树选择,可留空 |
| 项目 | 可多选,可留空 |

保存后,用户列表会出现新用户,状态应为「正常」。系统同时创建该用户的个人主 Key。

> **注意**:超级管理员(admin)默认不在人员管理列表中显示,这是设计行为,避免误删超管账户。

#### 给用户分配资源

1. 进入「AI 身份 > AI 身份管理」。
2. 选择「人员」标签,搜索用户名或姓名。
3. 找到用户的主 Key,点击「编辑」。
4. 在「可用 AI 资源」中勾选模型、MCP、Skill 或智能体。
5. 设置预算和限流。
6. 点击「保存」。

完成标志:列表中的「资源」列显示刚分配的资源数量,Key 状态为「已启用」。再用该用户登录用户端,打开「我的 AI 身份」,确认资源已经出现。

#### 设置预算

| 模式 | 填写方法 |
|------|---------|
| 统一预算 | 所有已选资源共用一个金额 |
| 分类预算 | 分别设置模型和 MCP 预算,可继续细分到单个资源 |
| 自定义 | 为每个已选模型或 MCP 单独填写金额 |

周期可选日、周或月。预算用于展示和归集,达到金额后不会自动停用 Key。

#### 设置调用限制

| 模式 | 填写方法 |
|------|---------|
| 不限流 | 不设置平台侧 RPM、TPM 和并发限制 |
| 总限流 | 为整个 Key 设置 RPM、TPM 和最大并发 |
| 分模型限流 | 为每个已选模型分别设置 RPM 和 TPM |

保存后,用该 Key 发起一次请求。返回 429 时,重新打开 Key 检查限制值;还要确认模型部署没有开启「透传」。

#### 创建场景 Key

1. 在 AI 身份管理中找到该用户。
2. 点击右侧「+场景 Key」。
3. 选择场景,填写 Key 名称和描述。
4. 单独选择资源、预算和限流。
5. 点击「保存」,复制新 Key 到对应客户端。

个人主 Key 用于用户日常使用,场景 Key 用于独立业务。不要把个人主 Key 交给多人共用。

#### 批量设置

1. 点击页面右上角「批量设置」。
2. 选择人员范围。
3. 选择要修改的资源、预算或限流。
4. 核对影响人数并确认。
5. 抽查一个用户的 Key 详情和用户端页面。

#### 停用用户或 Key

- 员工离职:在「人员管理」点击该用户的「禁用」。
- 单个场景停用:在「AI 身份管理」停用对应 Key。
- Key 泄露:先停用旧 Key,再查日志、创建新 Key、更新客户端,最后删除旧 Key。

停用后用旧 Key 测试一次,确认请求已经被拒绝。

### 模型纳管

按供应商、凭证、模型和部署的顺序接入模型。后台入口包括「供应商管理」和「模型管理」。

**首次接入流程**:
1. 选择供应商类型和接入格式。
2. 创建供应商和凭证,并完成凭证测试。
3. 创建模型、添加部署并完成模型测试。
4. 发布模型,配置多部署路由或 Fallback。
5. 进入「AI 身份 > AI 身份管理」,把模型分配给测试用户。
6. 使用测试用户的 Key、Endpoint 和模型 ID 发起调用。
7. 进入「资源审计 > 日志管理」确认调用记录。

**配置关系**:

```
供应商
  └─> 凭证:接入格式、API Base、API Key
       └─> 部署:平台模型 ID、厂商模型名、价格、路由参数
            └─> 模型:发布到用户端并分配给 AI 身份
```

| 对象 | 在哪里创建 | 保存什么 |
|------|----------|---------|
| 供应商 | 供应商管理 | 上游类型和允许使用的接入格式 |
| 凭证 | 供应商管理 | 一种接入格式、API Base 和 API Key |
| 模型 | 模型管理 | 用户端名称、分类、能力标签和说明 |
| 部署 | 模型管理的「添加凭证」 | 平台模型 ID、厂商模型名、凭证、定价和路由参数 |

员工使用平台模型 ID,管理员在部署中填写厂商模型名。两者可以不同。

#### 供应商类型与接入格式

创建供应商时选择正确的类型和接入格式。创建供应商前,从上游控制台或接口文档确认以下信息:
- 服务由哪家厂商或哪套推理服务提供。
- API Base。
- API Key。
- 接口示例使用 /v1/chat/completions、/v1/responses 还是 /v1/messages。

##### 选择供应商类型

在「模型纳管 > 供应商管理 > 新建」的「类型」下拉框中,按真实上游选择。列表中没有对应项时选「其他」。

| 实际上游 | 选择类型 | 常用接入格式 |
|---------|---------|------------|
| OpenAI | OpenAI | OpenAI |
| Anthropic | Anthropic | Anthropic |
| Azure OpenAI | Azure OpenAI | OpenAI |
| Google Gemini | Google | OpenAI |
| DeepSeek | DeepSeek | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| AWS Bedrock | AWS Bedrock | OpenAI |
| Vertex AI | Vertex AI | OpenAI |
| 火山引擎 | 火山引擎 | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| 阿里云百炼 | 百炼 | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| 智谱 | 智谱 | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| Moonshot | Moonshot | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| MiniMax | MiniMax | OpenAI;上游提供 Messages 接口时也可选 Anthropic |
| 小米 MiMo | 小米 MiMo | 按上游开放的接口选择 |
| vLLM | vLLM | OpenAI;服务端开放 Messages 接口时也可选 Anthropic |
| SGLang | SGLang | OpenAI |
| Ollama | Ollama | Ollama |
| LM Studio | LM Studio | LM Studio |
| 未列出的兼容服务 | 其他 | OpenAI 或 Anthropic |

不要因为模型名中有 Claude、GPT 或 DeepSeek,就改变供应商类型。例如,Bedrock 上的 Claude 仍然选择「AWS Bedrock」。

##### 选择接入格式

接入格式看 API 请求协议,不看下游客户端。

| 上游接口特征 | 选择格式 |
|------------|---------|
| 文档使用 OpenAI SDK,或路径为 /v1/chat/completions、/v1/responses、/v1/embeddings | OpenAI |
| 文档使用 Anthropic SDK,或路径为 /v1/messages | Anthropic |
| 上游服务是 LM Studio | LM Studio |
| 上游服务是 Ollama | Ollama |

Claude Code 是下游客户端,不是判断上游格式的依据。上游只提供 OpenAI 兼容接口时,凭证必须选择 OpenAI。

##### API Base 怎么填

API Base 填基础地址或版本根路径,不填具体业务接口。

| 地址 | 是否可用 |
|------|---------|
| `https://api.openai.com/v1` | 可以 |
| `https://api.deepseek.com` | 可以 |
| `https://gateway.example.com/v1` | 按该网关文档确认 |
| `https://api.example.com/v1/chat/completions` | 不可以,包含了具体接口 |
| `https://api.example.com/v1/messages` | 不可以,包含了具体接口 |
| `https://console.example.com` | 不可以,这是控制台网页 |

##### 配置错误时的表现

| 现象 | 先检查 |
|------|--------|
| 保存凭证后测试返回 404 | 接入格式是否选错;API Base 是否带了具体接口路径 |
| 返回协议或参数错误 | OpenAI 与 Anthropic 格式是否选反 |
| 自建服务连接超时 | ChateTokenManager 所在服务器是否能访问该地址;不要填写只在本机有效的 127.0.0.1 |
| Claude Code 找不到模型 | 先确认 Anthropic 部署测试成功,再使用带 (Anthropic) 后缀的模型 ID |

#### 供应商与凭证

在管理后台创建供应商、添加凭证并完成测试。一套可用配置的关系是:供应商下面创建凭证,模型部署再选择凭证。

```
供应商 -> 凭证(格式、API Base、API Key) -> 模型部署(平台模型 ID、厂商模型名)
```

##### 创建供应商

1. 进入「模型纳管 > 供应商管理」。
2. 点击供应商列表右上角「新建」。
3. 按下表填写。
4. 点击「保存」。

| 字段 | 填写方法 |
|------|---------|
| 名称 | 填便于管理员识别的名称,例如「DeepSeek 生产」 |
| 类型 | 选择真实上游;没有对应项时选「其他」 |
| 接入格式 | 只勾选上游实际支持的格式,可多选 |
| 描述 | 可填写账号、区域或用途,不要填写 API Key |

类型和格式不确定时,先查供应商类型与接入格式。完成后,左侧供应商列表会出现新记录。点击该记录,右侧显示凭证区域。

##### 创建凭证

1. 在左侧选中刚创建的供应商。
2. 点击右上角「新建凭证」。
3. 按下表填写。
4. 点击「保存」。

| 字段 | 填写方法 |
|------|---------|
| 凭证名称 | 填账号或线路名称,例如 deepseek-prod-cn |
| 接入格式 | 从该供应商已勾选的格式中选择一种 |
| API Base | 填基础地址,不要填 /chat/completions 或 /messages |
| API Key | 粘贴上游密钥;Ollama 未启用鉴权时可留空 |

一套凭证只选一种格式。上游同时提供 OpenAI 和 Anthropic 接口时,创建两套凭证。保存后,凭证卡片应显示名称、格式、API Base 和「启用」状态。

##### 测试凭证

1. 找到新凭证卡片。
2. 点击卡片右侧「测试」。
3. 等待测试结果。

测试成功后再创建模型。测试失败时按返回结果处理:

| 结果 | 处理 |
|------|------|
| 401 或 403 | 重新粘贴 API Key;确认密钥未过期且账号已开通接口权限 |
| 404 | 删除 API Base 末尾的具体接口路径;检查接入格式是否正确 |
| 400 或 422 | 检查 OpenAI 与 Anthropic 是否选反 |
| 连接超时 | 从 ChateTokenManager 服务器检查域名、端口、防火墙和内网路由 |
| 凭证测试成功,模型测试失败 | 到模型部署检查厂商模型名和模型分类 |

##### 编辑、禁用或删除

- 修改地址或密钥:点击凭证卡片的「编辑」,保存后重新测试。
- 临时停用线路:点击凭证卡片的「禁用」。引用该凭证的部署将不可用。
- 删除凭证:先删除或改绑引用它的模型部署,再点击「删除」。
- 删除供应商:先处理其下全部凭证和关联部署。

轮换 API Key 时,先新建一套凭证并测试,再把部署切换到新凭证,最后停用旧凭证。

#### 模型与部署

创建模型、添加上游部署并完成连通性测试。开始前,先确认要使用的凭证已经测试成功。

##### 新建模型

1. 进入「模型纳管 > 模型管理」。
2. 点击模型列表右上角「新建」。
3. 填写模型信息。
4. 点击「保存」。

| 字段 | 填写方法 |
|------|---------|
| 模型名称 | 用户端显示名称,例如「Claude Sonnet 4.6」 |
| 分类 | 按用途选择「对话」「向量」或「重排」 |
| Logo | 选择用户端模型卡片使用的图标 |
| 能力标签 | 按模型实际能力勾选图像、推理、工具调用等标签 |
| 描述 | 填适用场景和限制,不要填写密钥或上游地址 |

保存后,模型会出现在左侧列表中。此时模型还不能调用,必须继续添加部署。

##### 添加部署

1. 在左侧选中刚创建的模型。
2. 点击右上角「添加凭证」。
3. 填写平台模型 ID。
4. 选择供应商和凭证。
5. 填写厂商模型名。
6. 点击「添加」。

| 字段 | 填写方法 |
|------|---------|
| 模型 ID(用户请求时使用) | 自定义平台统一 ID,例如 claude-sonnet-4-6;发布后员工使用这个值 |
| 供应商 | 选择凭证所属供应商 |
| 凭证 | 选择已经测试成功的凭证 |
| 厂商模型名 | 填上游接口要求的准确模型名,例如 claude-sonnet-4-20250514 |
| 备注名称 | 填线路名称,例如「官方直连」或「华东生产」 |

平台模型 ID 和厂商模型名不是同一个字段:
- 员工请求:`claude-sonnet-4-6`
- 上游请求:`claude-sonnet-4-20250514`

选择 Anthropic 格式凭证时,系统还会注册带后缀的模型 ID:`claude-sonnet-4-6(Anthropic)`。Claude Code 使用带后缀的 ID,OpenAI 兼容客户端使用不带后缀的 ID。

##### 设置高级参数

在「添加凭证」窗口展开「高级设置」。没有明确需求时保留默认值。

| 字段 | 何时修改 |
|------|---------|
| 权重 | 同一模型有多条部署,需要按比例分配请求时修改 |
| 优先级 | 需要固定主线路和备用线路时修改;数字越小优先级越高 |
| 标签 | 需要按线路标签路由时填写,多个标签用逗号分隔 |
| 超时 | 上游响应较慢,需要增加单次请求等待时间时修改 |
| 流式超时 | 流式响应有单独超时要求时填写 |
| 最大重试 | 上游偶发失败时修改;增加后会延长请求时间 |

##### 定价

选择计费方式后按页面单位填写:
- **Token 计费**:单位为「元/百万 Token」,分别填写输入、输出、缓存读取和缓存写入价格。
- **按次或包月次数**:填写每次调用价格,不要把整月套餐价格填成单次价格。
- **外部价格**:供应商实际收费。
- **内部价格**:企业用于部门或项目归集的价格。

价格填错会直接影响成本报表。保存后到「AI 效能 > 成本」检查一笔测试调用的金额。

##### 其他开关

| 开关 | 操作要求 |
|------|---------|
| 透传 | 默认关闭。开启后页面提示 RPM/TPM 限流不生效 |
| 丢弃不支持参数 | 只有上游明确报「不支持参数」时再开启 |

##### 测试部署

1. 在模型详情中找到新部署。
2. 点击部署卡片的「测试」。
3. 输入测试内容并发送。
4. 确认页面返回了模型内容。

完成标志:测试状态成功,并且响应内容、耗时和 Token 数据正常。

| 测试结果 | 处理 |
|---------|------|
| 401 或 invalid key | 返回供应商管理,编辑凭证并重新测试 |
| 404 | 检查 API Base 是否包含具体接口;检查厂商模型名 |
| model not found | 从上游控制台复制厂商模型名,不要填写平台模型 ID |
| unsupported parameter | 减少测试参数;确认后再使用「丢弃不支持参数」 |
| 超时 | 检查网络和上游状态;必要时增加部署超时 |
| OpenAI 成功、Anthropic 失败 | 检查 Anthropic 凭证是否真的支持 /v1/messages |

##### 添加第二条部署

再次点击「添加凭证」,选择另一套凭证并填写厂商模型名。每条部署都要单独测试成功。同一模型下的部署应提供相同类别和相近能力。不要把对话模型和向量模型放在同一个平台模型 ID 下。

#### 发布与路由

发布已测试的模型,并配置多部署路由和故障切换。

##### 发布模型

1. 进入「模型纳管 > 模型管理」。
2. 选中已经测试成功的模型。
3. 点击右上角「发布设置」。
4. 开启「发布到用户端」。
5. 选择可见范围。
6. 按需勾选「领用前需要审批」。
7. 点击「保存」。

| 设置结果 | 说明 |
|---------|------|
| 全部用户 | 所有用户都能在模型广场看到该模型 |
| 指定部门 | 只有所选部门的用户可见 |
| 领用前需要审批 | 用户提交申请,管理员批准后才能调用 |
| 不需要审批 | 符合可见范围的活跃用户可直接获得资源 |

完成后,使用普通测试账号打开「模型广场」,确认模型卡片和接入信息正常。如果用户看得到模型但返回 model not allowed,进入「AI 身份 > AI 身份管理」,确认该用户的主 Key 已包含模型。

##### 临时停用一条线路

上游线路故障时:
1. 打开模型详情。
2. 找到故障部署。
3. 点击部署卡片的「禁用」。
4. 测试同一模型的其他启用部署。

只关闭「发布到用户端」不会立即处理已经持有 Key 的调用。需要止损时禁用部署或用户 Key。

##### 配置全局路由

只有同一模型配置了多条部署时才需要修改路由。

1. 在模型管理页面点击「路由配置」。
2. 选择路由策略。
3. 填写失败摘除、冷却、重试和超时参数。
4. 点击「保存」。

| 策略 | 使用场景 |
|------|---------|
| 轮询 simple-shuffle | 多条同能力线路分摊请求 |
| 最低延迟 latency-based-routing | 优先使用近期响应较快的线路 |
| 最低成本 cost-based-routing | 各部署价格已经准确填写 |
| 最少使用 least-busy | 优先使用当前较空闲的线路 |
| 按用量均衡 usage-based-routing | 按累计用量分配请求 |

| 参数 | 填写方法 |
|------|---------|
| 连续失败摘除 | 一条部署连续失败多少次后临时移出路由 |
| 冷却时间 | 被移出的部署等待多少秒后重新参与路由 |
| 全局重试次数 | 路由层最多重试次数 |
| 全局超时 | 路由层总等待时间 |

部署本身也有重试和超时。修改全局值后,用实际客户端检查总等待时间是否可接受。

##### 添加 Fallback

1. 在「路由配置」的 Fallback 链中选择源模型。
2. 选择源模型失败时使用的备用模型。
3. 点击「添加」。
4. 点击「保存」。

备用模型必须与源模型属于同一类别。对话模型不能回退到向量或重排模型。

##### 验证路由

1. 分别测试每条部署。
2. 连续调用同一平台模型 ID,确认日志中的供应商或部署符合所选策略。
3. 临时禁用一条测试部署,再次调用。
4. 确认剩余部署或 Fallback 能返回结果。
5. 恢复被禁用的部署。

| 状态 | 下一步 |
|------|-------|

| 建议修改 | 打开报告,按风险项修改 Skill 后重新上传和审查 |
| 高风险 | 不要发布;先处理报告中的高风险项 |

1. 在结果卡片点击「查看报告」。
2. 先核对 Skill 名称、版本、包哈希和报告编号。
3. 查看总体结论和高风险数量。
4. 逐条打开风险项,核对文件、行号、代码片段和处理建议。
5. 修改 Skill 后上传新版本,再点击「重新审查」。

| 报告结果 | 管理员操作 |
|---------|----------|
| 没有高风险,风险项可接受 | 记录审查结果后发布 |
| 存在可修复问题 | 修改对应文件,上传新包并重新审查 |
| 存在命令执行、凭证读取、数据外传等高风险 | 停止发布,交由 Skill 维护者处理 |
| 报告版本与当前包不一致 | 对当前包重新发起审查 |

审查报告不会自动阻止发布。管理员需要根据报告决定是否开启「发布到用户端」。

4. 点击「保存」。
5. 对测试 Skill 发起一次重新审查。
6. 打开报告,确认模型复核部分已完成。

模型复核失败时,规则扫描结果仍会保留。报告会标明模型复核是否完成。

#### 审查失败

| 现象 | 处理 |
|------|------|
| 提示没有 zip 包 | 返回 Skill 编辑页,上传并保存 zip 包 |
| 长时间停留在审查中 | 刷新列表;10 分钟仍无变化时记录 Skill 名称、版本和任务时间,交给部署负责人 |
| 扫描超时 | 检查包大小和文件数量,用较小的测试包重试 |
| 模型复核失败 | 测试所选模型和凭证;确认模型为已启用的 OpenAI 格式对话模型 |
| 报告只有规则扫描 | 检查模型复核开关和报告中的失败说明 |
| 重新上传后仍看到旧结果 | 核对报告编号、包哈希和版本,打开最新任务 |

### Claude Code 接入

把 Claude Code 连接到 ChateTokenManager。

#### 准备信息

从 ChateTokenManager 用户端取得:

| 信息 | 获取位置 |
|------|---------|
| AI 身份 Key | 我的 AI 身份 |
| Endpoint | 模型广场 > 查看接入信息 |
| Anthropic 模型 ID | 模型广场 > 查看接入信息,通常带 (Anthropic) 后缀 |

如果页面没有 Anthropic 模型 ID,请联系管理员确认该模型是否支持 Claude Code 接入。

#### 配置 Claude Code

编辑用户配置文件:
- macOS、Linux:`~/.claude/settings.json`
- Windows:`%USERPROFILE%\.claude\settings.json`

```json
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<ChateTokenManager Endpoint>",
    "ANTHROPIC_AUTH_TOKEN": "<AI 身份 Key>",
    "ANTHROPIC_MODEL": "<模型 ID>(Anthropic)"
  }
}
```

保存前检查:
- `ANTHROPIC_BASE_URL` 使用模型广场提供的 Endpoint,不要追加 /v1/messages。
- `ANTHROPIC_AUTH_TOKEN` 填 AI 身份 Key,不是供应商 Key 或管理 API Key。
- `ANTHROPIC_MODEL` 完整保留 (Anthropic) 后缀。
- JSON 最后一项后面不要有逗号。

#### 启动

进入工作目录后运行:
```bash
claude
```
第一次进入目录时,按提示确认是否信任该目录。

#### 验证

在 Claude Code 中依次运行:
```
/status
/model
```
确认 Base URL 指向 ChateTokenManager,模型与配置文件一致。然后发送一个简单问题,再让 Claude Code 读取一个测试文件,确认普通问答和工具调用都正常。

#### 常见问题

| 现象 | 处理方法 |
|------|---------|
| 启动后仍要求官方登录 | 关闭 Claude Code,检查配置文件路径和 JSON 格式后重启 |
| /status 不是 ChateTokenManager 地址 | 系统环境变量可能覆盖配置,检查旧的 ANTHROPIC_BASE_URL |
| 401 | 重新复制 AI 身份 Key,确认身份已激活 |
| model not found | 使用模型广场提供的完整 Anthropic 模型 ID |
| model not allowed | 联系管理员为你的 AI 身份分配该模型 |
| 普通问答成功但工具失败 | 换用标记「工具调用」的模型,并联系管理员检查模型能力 |

### Codex 接入

把 Codex CLI 连接到 ChateTokenManager。

#### 准备信息

从 ChateTokenManager 用户端取得 AI 身份 Key、Endpoint 和普通模型 ID。Codex 不使用带 (Anthropic) 后缀的模型 ID。

#### 保存 Key

macOS 或 Linux:
```bash
export CHATE_API_KEY="<AI 身份 Key>"
```

PowerShell:
```powershell
$env:CHATE_API_KEY = "<AI 身份 Key>"
```

#### 配置 Codex

编辑:
- macOS、Linux:`~/.codex/config.toml`
- Windows:`%USERPROFILE%\.codex\config.toml`

```toml
model_provider = "chate"
model = "<模型 ID>"

[model_providers.chate]
name = "ChateTokenManager"
base_url = "http://<ChateTokenManager Endpoint>/v1"
env_key = "CHATE_API_KEY"
wire_api = "responses"
```

`base_url` 填到 /v1,不要写成 /v1/responses。`env_key` 填环境变量名称,不要把真实 Key 写进 TOML。

#### 启动和验证

```bash
codex
```

也可以先执行一次简单测试:
```bash
codex exec "只回复:Codex 连接成功"
```

启动信息中的 provider 应为 chate,model 应为模型广场中的模型 ID。普通回答成功后,再在测试目录验证读取文件和执行简单任务。

#### 常见问题

| 现象 | 处理方法 |
|------|---------|
| 缺少环境变量 | 在启动 Codex 的同一终端设置 CHATE_API_KEY |
| 404 | base_url 应以 /v1 结尾,不要追加 /responses |
| 401 | Key 无效、已停用或没有传给当前进程 |
| model not allowed | 联系管理员为 AI 身份分配目标模型 |
| 自定义模型提示 unknown model | 先确认任务是否成功,再测试上下文和工具能力 |

## 常见问题

### 当前文档对应什么版本?
当前文档对应 ChateTokenManager 最新版本。

### 供应商、凭证、模型和部署是什么关系?
```
供应商 1 ─> N 凭证
模型   1 ─> N 部署
部署   N ─> 1 凭证
```
供应商定义服务类型,凭证保存地址和 Key,模型是员工看到的资源,部署负责把模型映射到具体凭证和厂商模型名。

### 为什么模型页的按钮叫「添加凭证」?
这个操作实际会创建部署。除了选择凭证,还要填写平台模型 ID、厂商模型名、路由、超时和定价。

### 平台模型 ID 和厂商模型名有什么区别?
平台模型 ID 是员工请求里的 model。厂商模型名只在部署中使用,是 ChateTokenManager 调上游时发送的值。两者可以不同。

### 为什么 Anthropic 模型 ID 带 (Anthropic)?
平台用后缀区分同一逻辑模型的 OpenAI 和 Anthropic 格式注册。Claude Code 和 /v1/messages 使用带后缀 ID,OpenAI 客户端使用普通 ID。

### 用户能看到模型,为什么调用仍失败?
可见性和调用权限分开。依次检查:
1. 用户是否完成领用审批。
2. 个人主 Key 是否包含模型。
3. 模型和部署是否启用。
4. Key 是否启用。
5. Endpoint 和模型 ID 是否复制正确。

### 我的 AI 身份页面为什么没有 Endpoint?
当前用户端在「我的 AI 身份」显示 Key,在「模型广场 > 查看接入信息」显示 Endpoint 和模型 ID。接入时要从两个页面取值。

### 支持哪些接口?
平台支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。具体模型是否支持工具调用、图像或特殊推理参数,取决于管理员接入的模型服务。

### RPM、TPM 和最大并发是什么?
- RPM 是每分钟请求数。
- TPM 是每分钟 Token 数。
- 最大并发是同一时间处理中的请求数。

AI 身份支持总 RPM、总 TPM、最大并发,以及按模型 RPM/TPM。

### 为什么设置了限流却没有生效?
先检查模型部署是否开启「透传」。当前页面明确提示透传会让 RPM/TPM 等限流不生效。再检查限流模式是否保存并同步到正确 Key。

### 预算达到后会自动停用吗?
预算主要用于展示和归因,达到金额后不会自动停用。需要立即停止调用时,使用调用限制、停用 Key 或移除资源。

### 为什么调用成功后日志页面没有记录?
调用记录通过后台定时任务从 LiteLLM 同步,默认每 5 分钟一次,加上 LiteLLM 写入延迟,实际看到日志可能需要 5-10 分钟。实时问题先在模型部署页测试,稍后再刷新日志管理页面。

### 为什么 token 用量有记录但成本为 0?
成本计算依赖模型部署中配置的单价(input_cost/output_cost)。如果部署未配价,即使 token 正常记录,external_cost 和 internal_cost 也会是 0。解决方法:
1. 进入「模型纳管 > 模型管理」。
2. 编辑对应部署,填写外部/内部输入价和输出价(单位:¥/百万 token)。
3. 保存后,新调用会正常计算成本。
4. 历史记录需要触发 `llm_log.recalc_cost` 任务重算。

### 为什么人员管理看不到 admin 用户?
超级管理员(is_super_admin=True)默认从人员管理列表中过滤掉,避免被误编辑或删除。这是设计行为。如需查看或编辑超管,可以直接查询数据库,或调整 `apps/repositories/user_repo.py` 的过滤条件。

### AI Policies 会自动拦截高风险 Skill 吗?
不会。它生成规则扫描和可选 LLM 复核报告,不修改文件,也不自动阻止发布。管理员要根据证据人工决定。

### AI Policies 是 OWASP 认证吗?
不是。风险分类参考 OWASP Agentic Skills Top 10,不表示 OWASP 对产品或报告认证、认可或背书。

### MCP、Agent 和 Prompt 都能做安全审查吗?
当前正式审查对象是 Skill zip 包。其他对象的审计在 AI 实验室中属于预告内容。

### Skill 和 MCP Server 如何交付给员工?
Skill 详情提供 Agent 安装提示词。MCP 详情提供 mcpServers 配置、工具清单和使用说明。需要审批的资源在批准后进入员工个人主 Key。

### 用户端支持英文吗?
支持中文和英文切换。语言设置不改变 API 配置。

### Key 泄露后怎么办?
1. 立即停用 Key。
2. 按 Key 和时间范围查调用日志。
3. 创建新 Key 并更新客户端。
4. 最后确认旧 Key 已无法调用。
5. 供应商 API Key 泄露时还要到上游控制台轮换凭证。
