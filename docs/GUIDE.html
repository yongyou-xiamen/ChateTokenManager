快速开始

产品介绍

ChateTokenManager 是面向企业的 AI 资源纳管平台,帮助企业管理 AI 资产、控制 AI 成本、衡量 AI 价值。管理员可以统一接入和分配 AI 资源,员工使用自己的 AI 身份访问所需工具,管理者可以持续查看使用量、成本和预算情况。

为什么使用 ChateTokenManager

企业开始大规模使用 AI 后,通常会遇到几类实际问题:

  • 模型和工具分散在不同供应商、账号和团队中,无法统一管理。
  • 员工各自保存密钥,人员变动后难以及时收回权限。
  • 不清楚哪些部门在使用 AI,也无法把成本归到具体人员、项目或模型。
  • 高成本模型、内部 Skill 和 MCP Server 缺少统一申请、审批和分发入口。
  • 出现异常调用后,缺少可查询的用户、Key、模型、用量和管理操作记录。

ChateTokenManager 把这些工作集中到管理后台。员工不需要接触供应商密钥,只使用自己的 AI 身份和管理员分配的资源。

三类用户

企业负责人 通过 Dashboard 和 AI 效能页面查看人员覆盖、调用趋势、模型使用、成本和预算执行情况。需要进一步分析时,可以按部门、项目、人员和模型查看数据。

平台管理员 负责日常配置和支持工作:

  • 接入企业采购或自建的模型服务。
  • 创建模型并完成可用性测试。
  • 建立人员、部门和项目。
  • 给员工分配 AI 身份、资源、预算和调用限制。
  • 发布模型、Skill、MCP Server 和智能体。
  • 处理员工申请,查询调用记录和管理操作记录。

普通员工 登录用户端后,可以查看自己的 AI 身份、已获授权的资源和本月用量。在模型广场或 AI 市场申请需要的资源,再把接入信息配置到 Claude Code、Codex、WorkBuddy 等工具中。

第一次使用

管理员 如果平台已经部署完成,建议按这个顺序开始:

  1. 进入「供应商类型与接入格式」,确认上游类型和接口格式。
  2. 按「供应商与凭证」保存服务地址和密钥。
  3. 按「模型与部署」创建模型、添加可用线路并测试。
  4. 发布模型,再为测试用户分配 AI 身份和模型权限。
  5. 使用测试用户登录用户端,完成一次真实调用。

普通员工:

  1. 使用管理员提供的账号登录用户端。
  2. 打开「我的 AI 身份」,确认状态为「已激活」。
  3. 打开模型广场或 AI 市场,申请所需资源。
  4. 审批通过后复制 Key、Endpoint 和模型 ID。
  5. 按对应的客户端文档完成配置。

使用指南

API Key 与管理 API

创建管理 API Key,让受信任的第三方系统调用 ChateTokenManager 管理 API。

管理后台「安全 > API Key」用于给第三方系统开放 ChateTokenManager 管理 API。例如,企业内部系统可以使用它读取人员、模型或资源信息,并按授权接口执行管理操作。

使用前确认

管理 API Key 权限等同管理员。创建前应确认:

  • 对接系统由企业管理,并且有明确负责人。
  • Key 只保存在服务端,不会下发到浏览器、桌面客户端或移动端。
  • 已确定用途、调用来源、有效期和停用流程。
  • 不把同一个 Key 分给多个无法区分的系统。

新建 API Key

进入「安全 > API Key」,点击「新建 API Key」。

字段必填填写建议
名称是使用「系统名-环境」,例如 oa-prod
描述否写清用途、负责人和对接系统
过期时间否有明确项目周期时设置;留空表示不过期

点击「创建」后,列表会显示新 Key。立即复制到对接系统的密钥存储中,不要写进代码仓库、配置样例或工单正文。

请求管理 API

ChateTokenManager 管理 API 的基础路径通常是:

http://<ChateTokenManager 地址>/api/v1

在请求头中使用:

Authorization: Bearer <管理 API Key>

下面的示例读取供应商列表,用于确认 Key 和地址是否正确:

curl "http://<ChateTokenManager 地址>/api/v1/providers?page=1&page_size=20" \
  -H "Authorization: Bearer <管理 API Key>"

成功时返回 code、message 和 data。具体字段以当前部署版本的接口文档为准。

查看接口文档

浏览器打开:

http://<ChateTokenManager 地址>/api/docs

在接口文档页面点击「Authorize」,输入管理 API Key,再选择接口进行测试。测试创建、修改和删除类接口时,先使用非生产数据,并记录测试对象。

状态与有效期

API Key 列表显示:

  • 当前状态:启用、禁用或已过期。
  • 创建时间。
  • 最后使用时间。
  • 过期时间。

「最后使用」长期为空时,先确认对接系统是否真的发送了该 Key,以及请求是否到达当前 ChateTokenManager 环境。

禁用和删除

临时停用

点击「禁用」后,使用该 Key 的新请求会被拒绝。故障排查、系统下线或发现异常来源时,优先禁用,确认无影响后再决定是否删除。

永久删除

删除前确认对接系统已经换用新 Key 或停止调用。删除后无法恢复,所有仍使用旧 Key 的请求都会失败。

轮换 Key

  • 新建一个用途相同的新 Key。
  • 把新 Key 更新到对接系统。
  • 观察新 Key 的「最后使用」时间。
  • 禁用旧 Key 并确认业务正常。
  • 删除旧 Key。

常见问题

现象检查方法
401Key 是否完整、是否禁用、是否过期,Authorization 格式是否正确
403当前接口是否允许 API Key 身份访问,或接口权限要求是否变化
404地址是否包含 /api/v1,接口路径是否属于当前版本
浏览器调用暴露 Key不要在前端直接调用,改由企业后端服务代理
无法判断哪个系统在调用为每个系统和环境创建独立 Key,不要共用

模型调用所需的 Key 请查看用户指南,不要使用本页的管理 API Key。

查看当天数据

使用快捷操作

管理指南

AI 身份

按部门、项目、人员和 AI 身份管理用户权限。

创建部门或项目

需要按组织管理用户时先创建归属:

  • 进入「AI 身份 > 部门管理」,创建部门并设置上级部门。
  • 跨部门项目进入「AI 身份 > 项目管理」创建。
  • 保存后返回人员管理创建用户。

不需要部门或项目时可以直接创建用户。

创建用户

  1. 进入「AI 身份 > 人员管理」。
  2. 点击右上角「新建用户」。
  3. 填写用户信息。
  4. 点击「保存」。
字段填写方法
用户名员工登录名,不能与已有用户重复
邮箱填有效邮箱地址
姓名填审批和用户端显示名称
密码设置初始密码,至少 6 位
角色普通员工选普通用户;需要进入管理后台时才分配管理员角色
部门从部门树选择,可留空
项目可多选,可留空

保存后,用户列表会出现新用户,状态应为「正常」。系统同时创建该用户的个人主 Key。

注意:超级管理员(admin)默认不在人员管理列表中显示,这是设计行为,避免误删超管账户。

给用户分配资源

  1. 进入「AI 身份 > AI 身份管理」。
  2. 选择「人员」标签,搜索用户名或姓名。
  3. 找到用户的主 Key,点击「编辑」。
  4. 在「可用 AI 资源」中勾选模型、MCP、Skill 或智能体。
  5. 设置预算和限流。
  6. 点击「保存」。

完成标志:列表中的「资源」列显示刚分配的资源数量,Key 状态为「已启用」。再用该用户登录用户端,打开「我的 AI 身份」,确认资源已经出现。

设置预算

模式填写方法
统一预算所有已选资源共用一个金额
分类预算分别设置模型和 MCP 预算,可继续细分到单个资源
自定义为每个已选模型或 MCP 单独填写金额

周期可选日、周或月。预算用于展示和归集,达到金额后不会自动停用 Key。

设置调用限制

模式填写方法
不限流不设置平台侧 RPM、TPM 和并发限制
总限流为整个 Key 设置 RPM、TPM 和最大并发
分模型限流为每个已选模型分别设置 RPM 和 TPM

保存后,用该 Key 发起一次请求。返回 429 时,重新打开 Key 检查限制值;还要确认模型部署没有开启「透传」。

创建场景 Key

需要把一个用户的不同业务分开统计时:

  1. 在 AI 身份管理中找到该用户。
  2. 点击右侧「+场景 Key」。
  3. 选择场景,填写 Key 名称和描述。
  4. 单独选择资源、预算和限流。
  5. 点击「保存」,复制新 Key 到对应客户端。

个人主 Key 用于用户日常使用,场景 Key 用于独立业务。不要把个人主 Key 交给多人共用。

批量设置

  1. 点击页面右上角「批量设置」。
  2. 选择人员范围。
  3. 选择要修改的资源、预算或限流。
  4. 核对影响人数并确认。
  5. 抽查一个用户的 Key 详情和用户端页面。

停用用户或 Key

  • 员工离职:在「人员管理」点击该用户的「禁用」。
  • 单个场景停用:在「AI 身份管理」停用对应 Key。
  • Key 泄露:先停用旧 Key,再查日志、创建新 Key、更新客户端,最后删除旧 Key。

停用后用旧 Key 测试一次,确认请求已经被拒绝。

管理指南

资源审计

处理资源申请、查询调用日志并下载导出文件。

审批管理

  1. 进入「资源审计 > 审批管理」。
  2. 将状态筛选为「待审批」。
  3. 按资源类型或申请人筛选。
  4. 核对申请人、部门、资源和申请理由。
  5. 点击「批准」或「拒绝」,填写备注并确认。

批准后,资源会加入申请人的个人主 Key。让用户刷新用户端;桌面客户端需要重启后读取新配置。

日志管理

  1. 进入「资源审计 > 日志管理」。
  2. 选择模型调用、MCP 调用、Skill 使用或智能体使用。
  3. 按调用时间、用户、模型或状态筛选。
  4. 打开记录查看 AI Key、供应商、错误、耗时和 Token。
日志结果处理
401检查用户、AI 身份 Key 和 Key 状态
403 或 model not allowed在 AI 身份管理中给用户分配模型
404 或 model not found核对模型 ID,再执行模型部署测试
429检查 RPM、TPM、并发限制和上游额度
500、502、503 或超时执行部署测试,检查上游状态和超时设置

导出任务

  1. 在日志页面设置筛选条件并点击「导出」。
  2. 进入「资源审计 > 导出任务」。
  3. 等待任务状态变为完成。
  4. 点击「下载」。

导出失败时记录任务时间和筛选范围,再重新创建一次导出任务。

管理指南

智能体中心

创建、发布和维护企业智能体入口。

进入「智能体中心 > 智能体列表」。

新建智能体

  1. 点击右上角「新建智能体」。
  2. 填写名称、分类、平台和说明。
  3. 填写用户访问智能体所需的地址或配置信息。
  4. 设置在线状态和是否发布。
  5. 点击「保存」。

保存后,智能体卡片会出现在列表中。用普通测试用户打开「智能体中心」,确认卡片、状态和访问入口正常。

编辑或下线

  1. 打开目标智能体。
  2. 修改信息后点击「保存」。
  3. 下线时关闭发布或在线状态。
  4. 使用普通用户账号确认该智能体已不可见或不可访问。

需要用户申请后使用时,在智能体发布设置中开启审批,并到「资源审计 > 审批管理」处理申请。

管理指南

AI 市场

发布和维护 Skill 与 MCP Server。

Skill 管理

  1. 进入「AI 市场 > Skill 管理」。
  2. 点击「新建」。
  3. 填写名称、作者、分类、版本、标签和描述。
  4. 填写 Markdown 使用说明并上传 zip 包。
  5. 点击「保存」。
  6. 发起安全审查,处理报告中的风险项。
  7. 开启「发布到用户端」,按需开启领用审批,再保存。

发布后,用普通测试用户打开 AI 市场,确认 Skill 详情和安装提示词正常。

MCP 管理

  1. 进入「AI 市场 > MCP 管理」。
  2. 点击「新建」。
  3. 填写连接和发布信息。
  4. 点击「保存」。
字段填写方法
名称用户端显示名称
唯一标识只使用字母、数字和下划线
URLMCP Server 连接地址
传输方式按服务端选择 SSE 或 Streamable HTTP
认证方式选择无、API Key、Bearer Token 或 Basic
认证值认证方式需要时填写
计费方式选择免费或按次计费
发布到用户端开启后进入 AI 市场
领用前需要审批开启后用户必须先申请

保存后打开 MCP 详情,确认工具发现成功并能生成接入配置。再用普通测试用户完成一次连接。

处理领用申请

需要审批的 Skill 或 MCP 由用户在 AI 市场提交申请。管理员进入「资源审计 > 审批管理」批准或拒绝。

  1. 进入「模型纳管 > 供应商管理」。
  2. 点击供应商列表右上角「新建」。
  3. 按下表填写。
  4. 点击「保存」。
字段填写方法
名称填便于管理员识别的名称,例如「DeepSeek 生产」

  1. 在左侧选中刚创建的供应商。
  2. 点击右上角「新建凭证」。
  3. 按下表填写。
  4. 点击「保存」。
字段填写方法

一套凭证只选一种格式。上游同时提供 OpenAI 和 Anthropic 接口时,创建两套凭证。保存后,凭证卡片应显示名称、格式、API Base 和「启用」状态。

测试凭证

  1. 找到新凭证卡片。
  2. 点击卡片右侧「测试」。
  3. 等待测试结果。

测试成功后再创建模型。测试失败时按返回结果处理:

结果处理
401 或 403重新粘贴 API Key;确认密钥未过期且账号已开通接口权限
404删除 API Base 末尾的具体接口路径;检查接入格式是否正确
400 或 422检查 OpenAI 与 Anthropic 是否选反
连接超时从 ChateTokenManager 服务器检查域名、端口、防火墙和内网路由
凭证测试成功,模型测试失败到模型部署检查厂商模型名和模型分类

编辑、禁用或删除

  • 修改地址或密钥:点击凭证卡片的「编辑」,保存后重新测试。
  • 临时停用线路:点击凭证卡片的「禁用」。引用该凭证的部署将不可用。
  • 删除凭证:先删除或改绑引用它的模型部署,再点击「删除」。
  • 删除供应商:先处理其下全部凭证和关联部署。

轮换 API Key 时,先新建一套凭证并测试,再把部署切换到新凭证,最后停用旧凭证。

  1. 打开模型详情。
  2. 找到故障部署。
  3. 点击部署卡片的「禁用」。
  4. 测试同一模型的其他启用部署。

配置全局路由

只有同一模型配置了多条部署时才需要修改路由。

  1. 在模型管理页面点击「路由配置」。
  2. 选择路由策略。
  3. 填写失败摘除、冷却、重试和超时参数。
  4. 点击「保存」。
策略使用场景
轮询 simple-shuffle多条同能力线路分摊请求
最低延迟 latency-based-routing优先使用近期响应较快的线路
最低成本 cost-based-routing各部署价格已经准确填写
最少使用 least-busy优先使用当前较空闲的线路
按用量均衡 usage-based-routing按累计用量分配请求
参数填写方法
连续失败摘除一条部署连续失败多少次后临时移出路由
冷却时间被移出的部署等待多少秒后重新参与路由
全局重试次数路由层最多重试次数
全局超时路由层总等待时间

部署本身也有重试和超时。修改全局值后,用实际客户端检查总等待时间是否可接受。

添加 Fallback

  1. 在「路由配置」的 Fallback 链中选择源模型。
  2. 选择源模型失败时使用的备用模型。
  3. 点击「添加」。
  4. 点击「保存」。

备用模型必须与源模型属于同一类别。对话模型不能回退到向量或重排模型。

验证路由

  1. 分别测试每条部署。
  2. 连续调用同一平台模型 ID,确认日志中的供应商或部署符合所选策略。
  3. 临时禁用一条测试部署,再次调用。
  4. 确认剩余部署或 Fallback 能返回结果。
  5. 恢复被禁用的部署。

其他

常见问题

ChateTokenManager 部署、模型、身份、预算、接口和审查问题。

供应商、凭证、模型和部署是什么关系?

供应商 1 ─> N 凭证
模型   1 ─> N 部署
部署   N ─> 1 凭证

供应商定义服务类型,凭证保存地址和 Key,模型是员工看到的资源,部署负责把模型映射到具体凭证和厂商模型名。

为什么模型页的按钮叫「添加凭证」?

这个操作实际会创建部署。除了选择凭证,还要填写平台模型 ID、厂商模型名、路由、超时和定价。

平台模型 ID 和厂商模型名有什么区别?

平台模型 ID 是员工请求里的 model。厂商模型名只在部署中使用,是 ChateTokenManager 调上游时发送的值。两者可以不同。

为什么 Anthropic 模型 ID 带 (Anthropic)?

平台用后缀区分同一逻辑模型的 OpenAI 和 Anthropic 格式注册。Claude Code 和 /v1/messages 使用带后缀 ID,OpenAI 客户端使用普通 ID。

用户能看到模型,为什么调用仍失败?

可见性和调用权限分开。依次检查:

  1. 用户是否完成领用审批。
  2. 个人主 Key 是否包含模型。
  3. 模型和部署是否启用。
  4. Key 是否启用。
  5. Endpoint 和模型 ID 是否复制正确。

我的 AI 身份页面为什么没有 Endpoint?

当前用户端在「我的 AI 身份」显示 Key,在「模型广场 > 查看接入信息」显示 Endpoint 和模型 ID。接入时要从两个页面取值。

支持哪些接口?

平台支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages。具体模型是否支持工具调用、图像或特殊推理参数,取决于管理员接入的模型服务。

RPM、TPM 和最大并发是什么?

  • RPM 是每分钟请求数。
  • TPM 是每分钟 Token 数。
  • 最大并发是同一时间处理中的请求数。

AI 身份支持总 RPM、总 TPM、最大并发,以及按模型 RPM/TPM。

为什么设置了限流却没有生效?

先检查模型部署是否开启「透传」。当前页面明确提示透传会让 RPM/TPM 等限流不生效。再检查限流模式是否保存并同步到正确 Key。

预算达到后会自动停用吗?

预算主要用于展示和归因,达到金额后不会自动停用。需要立即停止调用时,使用调用限制、停用 Key 或移除资源。

为什么调用成功后日志页面没有记录?

调用记录通过后台定时任务从 LiteLLM 同步,默认每 5 分钟一次,加上 LiteLLM 写入延迟,实际看到日志可能需要 5-10 分钟。实时问题先在模型部署页测试,稍后再刷新日志管理页面。

如果长时间(超过 1 小时)仍无记录,检查:1. celery worker 是否正常运行(docker compose logs aihelms | grep "llm_log.sync")。2. sync_state 表的 llm_logs 游标是否卡住。3. llm_call_logs.model 字段存的是 openai/<model>(带 provider 前缀),后台按模型筛选可能对不上,清除筛选条件看全部记录。

为什么 token 用量有记录但成本为 0?

成本计算依赖模型部署中配置的单价(input_cost/output_cost)。如果部署未配价,即使 token 正常记录,external_cost 和 internal_cost 也会是 0。解决方法:

  1. 进入「模型纳管 > 模型管理」。
  2. 编辑对应部署,填写外部/内部输入价和输出价(单位:¥/百万 token)。
  3. 保存后,新调用会正常计算成本。
  4. 历史记录需要触发 llm_log.recalc_cost 任务重算。

为什么人员管理看不到 admin 用户?

超级管理员(is_super_admin=True)默认从人员管理列表中过滤掉,避免被误编辑或删除。这是设计行为。如需查看或编辑超管,可以直接查询数据库,或调整 apps/repositories/user_repo.py 的过滤条件。

AI Policies 会自动拦截高风险 Skill 吗?

不会。它生成规则扫描和可选 LLM 复核报告,不修改文件,也不自动阻止发布。管理员要根据证据人工决定。

AI Policies 是 OWASP 认证吗?

不是。风险分类参考 OWASP Agentic Skills Top 10,不表示 OWASP 对产品或报告认证、认可或背书。

MCP、Agent 和 Prompt 都能做安全审查吗?

当前正式审查对象是 Skill zip 包。其他对象的审计在 AI 实验室中属于预告内容。

Skill 和 MCP Server 如何交付给员工?

Skill 详情提供 Agent 安装提示词。MCP 详情提供 mcpServers 配置、工具清单和使用说明。需要审批的资源在批准后进入员工个人主 Key。

用户端支持英文吗?

支持中文和英文切换。语言设置不改变 API 配置。

Key 泄露后怎么办?

  1. 立即停用 Key。
  2. 按 Key 和时间范围查调用日志。
  3. 创建新 Key 并更新客户端。
  4. 最后确认旧 Key 已无法调用。
  5. 供应商 API Key 泄露时还要到上游控制台轮换凭证。
